# 프로젝트 개요

현재 문서는 `v1.0.0` 기준 상태를 설명한다.

## 목표

BMS는 한 명의 네이버 블로그 운영자가 매일 쓰는 개인용 블로그 운영 비서다.

현재 제품은 아래 흐름을 한 앱 안에서 다룬다.

```text
키워드 순위 확인
-> 관심 키워드 변화 확인
-> 인기 키워드/상위글로 글감 찾기
-> 발행 전 본문 점검
-> 내 글 DB와 연결해 내부 링크/중복 주제 확인
```

## 운영 권장 상태

v1.0.0에서는 아래 운영 방식을 권장한다.

1. 노트북 또는 메인 PC 한 대를 기준 장비로 정한다.
2. 코드 동기화는 GitHub 저장소로 한다.
3. 실제 운영 데이터 동기화는 `data/bms.sqlite3` 파일 단위로 직접 옮긴다.
4. 두 PC에서 동시에 서로 다른 SQLite 복사본을 메인 DB처럼 쓰지는 않는다.

## 운영 모드

현재 가장 현실적인 운영 방식은 두 가지다.

### 1. 로컬 PC 운영

개인용으로는 PC를 켤 때 웹앱을 중심으로 실행해 쓰는 방식이 가장 단순하다.

- 웹앱: 가족가 브라우저에서 사용
- Discord 봇: 필요할 때만 켜는 선택 기능
- Playwright: 요청이 들어올 때 실제 네이버 화면을 조회

### 2. 소형 VM 운영

Oracle VM 같은 작은 서버에 웹앱만 상시 운영하고, Discord 봇이나 자동 감시는 후순위로 두는 방식이다.

현재 프로젝트는 Playwright가 핵심이라 서버리스보다 작은 VM과 더 잘 맞는다.

## 검색 기준

네이버는 같은 키워드라도 검색 표면마다 결과가 다르다. 따라서 결과를 섞지 않고 surface별로 분리한다.

| Surface | 설명 |
| --- | --- |
| `desktop` | PC 통합검색 |
| `mobile` | 모바일 통합검색 |
| `desktop_blog` | PC 블로그탭 |
| `mobile_blog` | 모바일 블로그탭 |
| `blog_section` | 네이버 블로그 섹션 |

예를 들어 어떤 키워드는 통합검색에서는 순위권 밖이어도 블로그탭에서는 상위권일 수 있다. 그래서 웹앱과 Discord 응답 모두 surface label을 함께 보여준다.

## 실행 명령

웹앱:

```bash
source venv/bin/activate
python scripts/run_web.py
```

기본 접속:

```text
http://127.0.0.1:8000
```

Discord 봇:

```bash
source venv/bin/activate
python bot/main.py
```

테스트:

```bash
source venv/bin/activate
pytest
```
